## 2. 데이터 구조

### 2-1. 설정값 (`config`)

| 키 | 값 | 설명 |
|---|---|---|
| `PLACES` | 강남, 잠실, 여의도, 성수, 종로, 홍대, 용산, 이태원, 문래 | 희망 장소 버튼 9개, 이 순서대로 3×3 배치 |
| `MENUS` | 한식, 중식, 양식, 일식, 아시안, 멕시칸, 샐러드 | 희망·기피 메뉴 버튼 7개, 3열 배치 |
| `SLOTS` | 점심, 저녁 | 시간대는 두 가지만 사용 |
| `DRINK` | O / △ / X + 상태 메시지 | 아래 표 참고 |
| `MENU_DB` | 카테고리별 세부 메뉴와 주의 재료 | 추천 메뉴용 예시 (성준님 DB로 교체 예정) |

음주 여부 버튼을 누르면 버튼 아래에 상태 메시지를 작게 보여줍니다.

| 값 | 버튼 표시 | 상태 메시지 |
|---|---|---|
| `O` | ○ | 오늘은 달려봐요! 끝까지 함께할게요 🍻 |
| `△` | △ | 분위기 보고 가볍게 한두 잔 할게요 |
| `X` | ✕ | 오늘은 쉬어갈게요. 음료로 건배해요 🥤 |

### 2-2. 모임 (`meeting`)

```json
{
  "name": "콘텐츠팀 회식",
  "code": "K7M2Q9",
  "inviteLink": "https://…/k7m2q9",
  "hostId": "조서윤2493",
  "createdAt": "2026-10-12T09:30:00+09:00",
  "responseMonth": "2026-10"
}
```

- `code`: 영문 대문자와 숫자 6자리. 헷갈리는 글자(O, 0, I, 1)는 만들지 않습니다.
- `inviteLink`: 모임 코드를 소문자로 붙인 주소. 실제 도메인은 배포 후 정합니다.

### 2-3. 참여자 (`participants[]`)

```json
{
  "id": "김민준3184",
  "isHost": false,
  "note": "갑각류 알레르기가 있어요",
  "slots": ["2026-10-16|저녁", "2026-10-22|저녁", "2026-10-23|저녁"],
  "places": ["강남", "여의도", "성수"],
  "likes": ["한식", "양식", "일식"],
  "dislikes": ["멕시칸"],
  "drink": "O"
}
```

| 필드 | 형식 | 규칙 |
|---|---|---|
| `id` | 이름 + 숫자 4자리 | 정규식 `^[가-힣A-Za-z]{1,10}\d{4}$`, 모임 안에서 중복 불가 |
| `isHost` | true / false | 방장도 초대 링크로 입장해 똑같이 투표 |
| `note` | 문자열, 비어도 됨 | 화면 이름은 "확인해주세요" |
| `slots` | `YYYY-MM-DD\|점심` 또는 `\|저녁` | 1개 이상 필수 |
| `places` | `PLACES` 중 0~3개 | |
| `likes` | `MENUS` 중 0~3개 | `dislikes`와 겹칠 수 없음 |
| `dislikes` | `MENUS` 중 0~3개 | `likes`와 겹칠 수 없음 |
| `drink` | `O`, `△`, `X`, null | 선택 안 하면 null |

### 04 응답 (한 페이지 스크롤)

예시 상태는 `김민준3184`가 다시 입장한 화면이에요. 달력에서 선택한 날짜는 연한 주황 배경, 지금 보고 있는 날짜(10/16)는 주황 테두리로 표시해요. 토요일은 파란색, 일요일은 빨간색이에요.

| 구분 | 값 |
|---|---|
| 선택 개수 제한 | 장소 3, 희망 메뉴 3, 기피 메뉴 3, 음주 1 |
| 비활성 규칙 | 3개를 고르면 나머지 버튼 비활성, 희망 메뉴로 고른 항목은 기피 메뉴에서 비활성 (반대도 같음) |
| 선택 색 | 연한 배경 + 같은 계열 진한 글자 + 테두리. 시간대 `#FFE3D1`/`#A33F00`, 장소 `#DDEBFB`/`#2F65BF`, 희망 메뉴 `#DDF2E6`/`#23784F`, 기피 메뉴 `#FDE3E8`/`#B83A52`, 음주 `#EEE4FB`/`#6A45B0` ([다음]·[확정하기]는 주황 배경 + 흰 글자 유지) |

아래 값이 테스트 데이터 10명의 정답이에요.

| 카드 | 표시 |
|---|---|

| 날짜 | **1위 10/23(금) 저녁 (10표)** [만장일치] / 2위 10/16(금) 저녁 (7표) / 공동 3위 10/22(목) 저녁 · 10/30(금) 점심 (4표) |
| 장소 | **1위 강남 (7표)** / 2위 성수 (6표) / 공동 3위 여의도 · 종로 (3표) |

### 06 상세 (아래에서 올라오는 시트)

날짜·장소·메뉴 카드의 [상세 ›]를 누르면 열려요. 대시보드와 같은 1~3위를 보여주고, 각 순위 아래에 그 항목을 고른 사람의 ID를 칩으로 보여줘요. 메뉴 상세는 좋아요와 싫어요를 나눠서 보여주고, 맨 아래 [닫기]는 다른 화면의 주요 버튼과 같은 주황 버튼이에요. 순위별 투표자 목록은 JSON의 `screens.06_detail`에 모두 들어 있어요.

## 5. 계산 규칙

**순위.** 표 수가 많은 순서로 정렬하고, 표 수가 같으면 같은 순위로 묶어 "공동 n위"로 표시해요. 다음 순위는 묶인 개수만큼 건너뛰어요(예: 공동 3위가 2개면 다음은 5위). 화면에는 1~3위만 보여주고, 0표 항목은 빼요. 공동 순위 안의 순서는 날짜는 빠른 순, 장소·메뉴는 `config` 목록 순서예요.

**만장일치.** 1위 항목의 표 수가 참여 인원과 같을 때만 [만장일치] 배지를 붙여요. 방장도 참여 인원에 들어가요.

**추천 메뉴.** 좋아요 1위 카테고리(공동이면 모두)의 `MENU_DB` 세부 메뉴 중에서, 모든 참여자의 "확인해주세요" 내용에 주의 재료(예: 갑각류, 매운)나 메뉴 이름(예: 마라탕)이 들어 있는 메뉴를 빼고 순서대로 보여줘요.

**요약 텍스트.** 좋아요는 1·2위 메뉴, 싫어요는 1위 메뉴만 넣어요. 0표인 음주 값은 빼고, 음주 응답이 하나도 없으면 "응답 없음"으로 써요.
